# Nova Expo Extension Failure-Mode Review

This review describes where extension operations can fail, which decisions must
remain with the user, and how the extension handles each case. It is intended to
be updated whenever a workflow is added.

## Execution policy

| Operation type                   | Required interaction                                                 | Examples                                                  |
| -------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------- |
| Local or remote read             | A clearly labelled action is sufficient                              | Project config, build history, account status             |
| Long-running local process       | Target selection plus a persistent task screen with Stop             | Metro, Expo Go, web dev server                            |
| Local file mutation              | Explanation of affected files and explicit confirmation              | Prebuild, variants, workflow templates, dependency fixes  |
| Remote mutation or possible cost | Destination/profile selection, impact summary, explicit confirmation | EAS build, update, deploy, metadata push                  |
| Production release               | Explicit confirmation plus a successful release gate                 | Production build, store submission, production OTA update |
| TTY-dependent operation          | Explanation followed by a real integrated terminal                   | Login, credentials, interactive EAS setup                 |
| New project                      | Validated wizard plus final complete summary                         | Nova Expo project creation                                |

## Failure points and mitigations

| Area                         | Failure point                                                                           | User impact                                                             | Detection and handling                                                                                                                                                                                                                                                                                                              | Residual consideration                                                                                                                                                                                                                                                                |
| ---------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Project discovery            | Expo app is nested in a monorepo or a secondary workspace root                          | Wrong project or no dashboard                                           | Searches up to 200 package manifests across all workspace roots and persists an explicit active project                                                                                                                                                                                                                             | Very large repositories with more than 200 package manifests may require opening the app folder directly                                                                                                                                                                              |
| Dynamic config               | `app.config.js` or `app.config.ts` cannot safely be evaluated inside the extension      | Some identifiers are not visible in the dashboard                       | Marks dynamic config explicitly; release checks resolve public config through Expo                                                                                                                                                                                                                                                  | Variant automation is blocked rather than overwriting custom logic                                                                                                                                                                                                                    |
| Workspace trust              | Project code is untrusted                                                               | Running scripts could execute repository code                           | The extension declares limited untrusted support: configuration is read, every command path refuses to spawn a process, and a persistent banner explains what trust unlocks                                                                                                                                                         | User must explicitly trust the workspace                                                                                                                                                                                                                                              |
| Prompt values                | A collected value begins with a dash and is parsed as an option by the workflow runtime | A release command could be silently redirected or turned into a dry run | Release-critical values travel as environment variables; prompts reject leading dashes; prepared arguments are refused if they contain a reserved runtime option                                                                                                                                                                    | Free-form values passed straight to the EAS CLI still follow that CLI's own parsing                                                                                                                                                                                                   |
| Task output encoding         | A pipe splits an escape sequence or a multi-byte character across chunks                | Control codes and replacement characters in the task log                | Each stream is decoded with a stateful UTF-8 decoder and holds back a partial escape sequence until it completes                                                                                                                                                                                                                    | Interactive terminals keep native terminal rendering                                                                                                                                                                                                                                  |
| Package managers on Windows  | `npm`, `pnpm`, `yarn`, and `bun` are `.cmd` shims that Node will not spawn directly     | Dependency installation fails to start                                  | The fixed package-manager command runs through the platform shell on Windows only                                                                                                                                                                                                                                                   | Shell resolution still depends on the user's PATH                                                                                                                                                                                                                                     |
| Shell/runtime                | Bash or Node is missing or incompatible                                                 | Process cannot start                                                    | Spawn errors appear in task output and a visible error summary; shell and Node paths are configurable                                                                                                                                                                                                                               | New projects require external Node 22.13+; Windows requires a compatible Bash/WSL configuration                                                                                                                                                                                       |
| Network/authentication       | npm, Expo, or EAS is unavailable or the session expired                                 | Cloud or install task fails                                             | Non-zero exit is retained with sanitized output and a VS Code error notification                                                                                                                                                                                                                                                    | The extension cannot repair service outages; retry after fixing connectivity/login                                                                                                                                                                                                    |
| Hidden CLI prompt            | A piped process unexpectedly asks for input                                             | Task could hang                                                         | Dashboard processes run with CI/non-interactive flags and closed stdin; known TTY workflows open in an integrated terminal                                                                                                                                                                                                          | Newly added workflows must be classified before being exposed                                                                                                                                                                                                                         |
| Concurrent tasks             | A second operation replaces or corrupts visible output                                  | Lost control over the first process                                     | Only one managed dashboard task can run, enforced by the runner itself as well as by its callers, and the user is directed to the active task                                                                                                                                                                                       | Independent integrated terminals remain under VS Code terminal control                                                                                                                                                                                                                |
| Development server           | Metro is keystroke-driven and prints a QR code                                          | A dashboard task cannot reload, open a target, or render the QR code    | The dev server opens in a real integrated terminal, which keeps every Expo keybinding and leaves the single managed-task slot free for a build or update to run alongside it                                                                                                                                                        | The terminal is stopped through VS Code's own terminal controls rather than the dashboard task screen                                                                                                                                                                                 |
| Cancellation                 | Killing the wrapper leaves Expo/EAS descendants alive                                   | Task appears stopped but child work continues                           | Sends SIGTERM to the process group and escalates to SIGKILL after three seconds; on Windows the tree is terminated through `taskkill /t /f`                                                                                                                                                                                         | Windows has no signals, so cancellation there is always immediate rather than graceful                                                                                                                                                                                                |
| Output volume                | Long builds exhaust webview memory                                                      | Slow or crashed UI                                                      | Extension retains a bounded 300k-character buffer and UI retains bounded lines                                                                                                                                                                                                                                                      | Full historical logs should still be obtained from Expo/EAS for deep incident analysis                                                                                                                                                                                                |
| Project creation target      | Folder exists, parent is missing, or parent is not writable                             | Accidental overwrite or partial project                                 | Parent comes from a folder picker; name is validated; writability and target nonexistence are checked twice                                                                                                                                                                                                                         | A race from another process is stopped if detected before launch; the initializer also refuses existing targets                                                                                                                                                                       |
| Project creation install     | Template download, npm install, or validation fails after the folder is created         | Partial project remains                                                 | Task output identifies the failing step and the extension explicitly reports the retained folder                                                                                                                                                                                                                                    | The extension never deletes partial work automatically; inspect or remove it before retrying the same name                                                                                                                                                                            |
| Package customization        | Invalid package name/version or incompatible Expo native package                        | Install or validation fails                                             | Validates npm specifiers before creation; required template packages cannot be removed; Expo alignment and final validation run by default                                                                                                                                                                                          | Custom packages remain the developer's compatibility responsibility                                                                                                                                                                                                                   |
| Optional native plugin       | Package is deselected but remains in Expo plugins                                       | Prebuild fails                                                          | Initializer builds the plugin list from selected packages                                                                                                                                                                                                                                                                           | Custom packages that require plugins may still need manual app-config changes                                                                                                                                                                                                         |
| EAS setup                    | Build/update/submit action runs without EAS profiles                                    | Confusing CLI failure                                                   | Cloud actions are blocked with a direct Configure EAS recovery action                                                                                                                                                                                                                                                               | Hand-written unusual EAS configurations may need terminal use                                                                                                                                                                                                                         |
| Build cost                   | Accidental remote build                                                                 | Time/quota usage                                                        | Requires profile/platform selection and an explicit cost-aware confirmation                                                                                                                                                                                                                                                         | Actual pricing and queue time are controlled by Expo                                                                                                                                                                                                                                  |
| Uncommitted changes          | The release gate refuses to validate a working tree with uncommitted or untracked files | Release actions stop before reaching EAS                                | The failure is classified with a Review Source Control next step, and continuing anyway is offered as a separate confirmation that names the consequence                                                                                                                                                                            | Releasing an uncommitted tree stays a deliberate, individually confirmed decision rather than a remembered preference The check is scoped to the project directory so an unrelated monorepo package cannot block it, and a project outside git is warned rather than silently passed. |
| Downloaded CLI versions      | `npx` installs a tool that is not present in the project                                | An unattended run picks up a newly published major                      | Downloaded EAS CLI and Expo Doctor versions default to the ranges pinned in `nova.pinned`, overridable through `EAS_CLI_VERSION` and `EXPO_DOCTOR_VERSION`                                                                                                                                                                          | Pinned ranges need review when a new major is adopted                                                                                                                                                                                                                                 |
| Executed script location     | A repository points the toolkit path at scripts it controls                             | Repository code runs under the user's identity                          | `novaExpo.toolkitPath` is declared `machine`-scoped and is read through `inspect`, so only the user's own global or remote value is honoured; a workspace or folder value is ignored and a relative path is refused                                                                                                                 | Trusting a workspace still allows the project's own tooling to run, as with tasks and debugging                                                                                                                                                                                       |
| Hidden webview               | The view is collapsed while a wizard or task is open                                    | The operation is silently cancelled                                     | The prompt bridge and the runner outlive the view; a reloaded webview announces itself and is sent the active task, the open wizard, and its previous screen                                                                                                                                                                        | A pending question is answered in the sidebar; it does not fall back to a modal                                                                                                                                                                                                       |
| Store-distribution build     | Invalid configuration or dirty repository                                               | Bad release artifact                                                    | Any profile whose distribution is not explicitly internal automatically runs the release gate before build                                                                                                                                                                                                                          | The user must resolve gate failures rather than bypass them in the extension                                                                                                                                                                                                          |
| OTA destination              | No configured update channel or a production channel with a custom name                 | Update could reach the wrong audience                                   | Publishing is blocked when no channel exists; store-distribution channel mappings trigger the selected profile/environment release gate                                                                                                                                                                                             | Channels inherited through complex EAS profile chains may not appear until represented explicitly                                                                                                                                                                                     |
| OTA traceability             | Empty release notes                                                                     | Hard-to-audit update                                                    | Release notes are required by the extension                                                                                                                                                                                                                                                                                         | EAS may accept additional metadata through advanced CLI use                                                                                                                                                                                                                           |
| Store submission             | Wrong build, platform, or profile                                                       | Incorrect store upload                                                  | Requires platform, submit profile, and explicit latest/ID/file source selection; readiness gate runs first                                                                                                                                                                                                                          | Store-side review and credential errors remain external                                                                                                                                                                                                                               |
| Destructive/remote workflows | Click immediately changes state                                                         | Unintended mutation                                                     | Every catalog action opens a review page carrying an explanation, the list of what it touches, and an Expo documentation link before it runs; Command Palette paths receive an explicit confirmation                                                                                                                                | `explanation`, `effects`, and `docsUrl` are required by the `ToolkitAction` type and asserted by tests, so an action cannot be added without them                                                                                                                                     |
| Success dead end             | A task succeeds and the user does not know what comes next                              | Setup stalls halfway through a release sequence                         | Every successful workflow attaches a follow-up: a named next action where one exists, otherwise the action's Expo documentation; the release path chains build to submission, submission to store status, and an update to its adoption metrics                                                                                     | The suggested step is the common path, not a prescription                                                                                                                                                                                                                             |
| Documentation links          | A correction names a Nova command but not the Expo concept behind it                    | The user repeats the fix without understanding it                       | Catalog actions and recovery suggestions each carry a `docsUrl`, opened through a host command that refuses any host other than Expo's own documentation over https                                                                                                                                                                 | Expo may reorganize its documentation; the links are checked as a set when they are changed                                                                                                                                                                                           |
| Error visibility             | Failure disappears after leaving the view                                               | User cannot diagnose or retry safely                                    | Error status, exit code, bounded output, inline feedback, corrective actions, and the recent-task card persist while the extension host lives                                                                                                                                                                                       | Task history is intentionally not written to disk and clears on full VS Code restart                                                                                                                                                                                                  |
| Recovery guidance            | A novice sees a CLI error but does not know the prerequisite or next command            | Repeated failures and abandoned setup                                   | Classifies retained output and project state, then links up to three relevant Nova corrections, each with the Expo documentation page behind it, from both the error popup and task screen. An unclassified failure falls back to a health check and the failing action's own documentation, so no failure ends at a bare exit code | Unknown external-service failures are linked to the documentation for the operation attempted, not to a specific cause                                                                                                                                                                |
| Secrets                      | Prompt/output leaks tokens                                                              | Credential exposure                                                     | Secret CLI flows use the integrated terminal; workflow command display redacts known secret flags                                                                                                                                                                                                                                   | Avoid passing secrets through generic custom commands or screenshots                                                                                                                                                                                                                  |

## Review checklist for every new action

1. Decide whether it is read-only, local mutation, remote mutation, costly,
   destructive, interactive, or persistent.
2. List every required parameter and collect it before process launch.
3. Validate project prerequisites without making changes.
4. Explain local files, remote resources, credentials, or quota the action can
   affect.
5. Require confirmation at the last reversible point.
6. Use dashboard execution only when the command is non-interactive; otherwise
   open a real terminal.
7. Verify cancellation and child-process cleanup for persistent commands.
8. Ensure a failure produces a helpful final line, non-zero exit, and recovery
   path.
